# ネットワーク復帰の確認手順

SPEC §10 の実機確認。自動テストで潰せる範囲と、人が手を動かさないと確認できない範囲を分けてある。

---

## 自動で確認済み

`npm run test:live` に含まれる（`VO_LIVE=1`）。

| 項目 | 内容 |
|---|---|
| 指紋の安定性 | 本物の `os.networkInterfaces()` から指紋を作り、何も変えなければ変化を報告しないこと |
| **二重実行の回避** | **実 claude のターンを作業中に切り、復帰させても編集が 1 回しか入らないこと**（§10.5 の設計の要） |
| 中断の扱い | 中断は `interrupted` として閉じ、`failed` に数えず経験値も減らさないこと |
| 復帰の記録 | `stats.reconnects` が増え、`idle` に戻ること |

オフラインテスト（`npm test`）側では、インターフェース表を差し替えて以下を検証している:

- WiFi 切替の中間状態（`169.254.x` を経由）を通っても、落ち着いた先だけを 1 回報告する
- 一瞬ぶれて元に戻った場合は報告しない
- 時計が飛んでいたらスリープ復帰とみなして安定判定を飛ばす
- 同居している社員は直列、worktree で隔離されていれば並行に復帰する
- セッション未確定のまま切れたら復帰せず、元の指示をメモへ書き戻す

## 人が手を動かして確認すること

インターフェースの物理的な切り替えは自動化できない。以下は実機で 1 度確認してほしい。

### 手順 1 — WiFi の切り替え

1. `npm start` で起動する
2. 社員を 1 人採用し、少し時間のかかる指示を出す
   （例:「このリポジトリの構成を調べて、気になる点を 3 つ挙げて」）
3. 社員が `WORKING` か `THINKING` の間に、**WiFi を別のアクセスポイントに切り替える**
   （テザリングへの切替でもよい）

**期待する挙動**

- 3 秒ほどで画面上部に `⚡ ネットワークが切り替わりました` と出る
- 対象の社員が `RECONNECT` になり、頭上に `⚡` が付く
- 数秒後に `⚡ 1 名が復帰しました` に変わり、社員が作業を再開する
- 会話モード（`Enter`）を開くと、中断と復帰の位置に区切り線が入っている
- **同じファイルが二重に編集されていない**

### 手順 2 — 待機中の切り替え（何も起きないこと）

1. 全員が `IDLE` の状態で WiFi を切り替える
2. **何のバナーも出ないこと**を確認する

1 ターン = 1 プロセスなので、待機中の社員はネットワーク変更の影響を受けない（§10.1）。
ここでバナーが出るようなら過剰検知なので、`config.json` の `network.stabilizeMs` を伸ばす。

### 手順 3 — スリープ復帰

1. 社員に指示を出し、**すぐにマシンをスリープさせる**
2. 数分後に復帰させる

**期待する挙動**: 起きた直後に検知が走る（安定判定を待たない）。復帰に失敗した場合は
社員が `ERROR` になるので、`R` キーで手動再接続できる。

### 手順 4 — 圏外からの復帰

1. WiFi を切って完全にオフラインにする
2. 社員に指示を出す → 失敗して `ERROR` になる
3. WiFi を戻す
4. 社員を選んで `R` を押す

**期待する挙動**: 再接続が走り、会話が続く。

## 感度の調整

過剰検知・検知漏れがあれば `~/.virtual-office/config.json` の `network` を触る。

```jsonc
"network": {
  "pollIntervalMs": 5000,        // 監視の間隔。短くすると反応が速いが CPU を食う
  "stabilizeMs": 3000,           // 指紋がこの時間だけ安定してから「変わった」と判定
  "maxWaitMs": 60000,            // ネットワーク復旧を待つ上限。超えたら error
  "maxRetries": 3,               // 復帰の再試行回数（2s → 8s → 32s）
  "sleepDetectThresholdMs": 60000, // 前回監視からこれ以上空いたらスリープ扱い
  "autoRecover": true            // false にすると検知して知らせるだけ
}
```

- **VPN の接続/切断で毎回反応してしまう** → `stabilizeMs` を伸ばす
- **切り替えても気づかない** → `pollIntervalMs` を短くする。それでも駄目なら `R` で手動
- **勝手に復帰してほしくない** → `autoRecover: false`。検知だけして `R` を待つ
