# AGENT DASHBOARD

`claude` と `codex` のセッションをまとめて見るターミナルのダッシュボードです。
どのセッションが何をしていて、コンテキストをどれだけ使い、いくらトークンを
消費したかが 1 画面で分かります。そのまま会話に入って指示を出せます。

```

## 動かす

```bash
npm start                    # ~/.agent-dashboard を使って起動
npm start -- --cwd ~/myrepo  # 既定の作業ディレクトリを指定
npm start -- --ascii         # ブロック文字を使わない描画
npm start -- --no-anim       # 動きを止める
npm start -- --no-bell       # 端末ベルを鳴らさない
```

必要なもの:

- Node.js 22.6 以上（TypeScript をそのまま実行します。ビルド不要）
- `claude` または `codex` のどちらか。両方あれば両方使えます

端末は **100x30 以上**にしてください。

## 基本の流れ

1. `n` でセッションを追加する（CLI・役割・作業ディレクトリを選ぶ）
2. `Enter` で会話に入り、プロンプトを書いて `Enter`
3. 一覧で状態・コンテキスト・トークンを見る
4. 終わったら `e` で次に送るプロンプトを書いておくと、`Enter` でそのまま送れる

主なキー（全一覧は `?`）:

| キー | できること |
|---|---|
| `↑↓` / `kj` | 行を選ぶ |
| `Enter` | 開く（承認待ちなら内容、下書きがあれば送信） |
| `e` / `d` | 次に送るプロンプトの編集 / 削除 |
| `n` / `X` | 追加 / アーカイブ |
| `Ctrl+C` | 実行中のタスクを中断 |
| `R` | 再接続 |
| `L` `a` `s` `,` `?` | ログ / 履歴 / 統計 / 設定 / ヘルプ |
| `q` | 終了 |

一覧の右側に出る印: `W` worktree で隔離 / `P` 下書きあり / `!` 承認待ち / `S` サブエージェント稼働中

## できること

### 使用量

両方の残量が上部に出ます。

- **claude** — `claude -p "/usage"` を叩きます。CLI 内部で処理されるので
  **モデル呼び出しは起きず、課金もされません**（約 0.4 秒）
- **codex** — `~/.codex/sessions/` の記録にある `rate_limits` を読みます

起動時・5 分ごと・実行が終わったときに取り直します。取れなかったときは
数字を作らず、その旨を出します。

### 会話は途切れません

1 ターンごとに CLI プロセスを起こして終える方式ですが、会話そのものは CLI 側の
セッションストアに残ります。**落として立ち上げ直しても、続きから話せます。**

### マークダウンを読める形で出す

モデルの応答に含まれる見出し・箇条書き・表・コードブロックは、記号のまま
出さずに装飾へ置き換えます。

```
  │ やったこと                      ← ## 見出し
  │
  │ src/auth/session.ts を直しました。期限切れの判定が UTC を仮定していたためです。
  │                                   ↑ `コード` は色付き、**太字** は強調
  │ • 検証を Date.now() 基準に変更   ← - 箇条書き
  │   • 期限切れ                     ← 入れ子は下げる
  │
  │   export function isExpired(token: Token): boolean {   ← コードブロックは
  │     return token.expiresAt <= Date.now();                 背景を変えて素通し
  │   }
  │
  │  項目     │ 変更前       │ 変更後   ← 表は桁を揃える
  │  ─────────┼──────────────┼───────
  │  判定基準 │ ローカル時刻 │ UTC
```

**中身は変えません。** 記号を装飾に置き換えるだけです。

- コードブロックの中は一切解釈しません（`**bold**` があってもそのまま）
- リンクの URL は捨てずに残します
- 記法として成立していない記号（`2 * 3`、`snake_case`）はそのまま出します

### 複数行を書く

会話の入力欄で改行するには **`Ctrl+J`** を押します。`Enter` は送信です。

`Alt+Enter` と `Shift+Enter` でも改行できますが、**この 2 つは端末やウィンドウ
マネージャに横取りされることがあります**（Alacritty などは Alt+Enter を全画面
切り替えに使います）。`Ctrl+J` はどの端末でもそのまま届くので、こちらを既定の
案内にしています。

### 文脈が長くなったら引き継ぐ

同じスレッドを続けるほど、1 ターンで送り直す量が増える。実測では 5 ターンで
23k → 92k トークン、長いものは 23 万に達していた。1 ターンの下地は 16k 程度なので、
途中で新しいセッションに移れば大きく減らせる。

`N` で、これまでの指示と結果の要約を引き継ぎ文にして新しいセッションを作り、
元のセッションを畳む。引き継ぎ文は手元のタスク履歴から組み立てるのでモデルを
呼ばない。入力欄に入れて渡すので、中身を見てから送れる。

文脈が 50% を超えると詳細パネルで知らせる。

## 使っているモデル

一覧の「モデル」列と、詳細パネルの「モデル」行に出る。`gpt-6-astra/high` のように
モデルと推論の深さを並べる（深さは codex のみ）。

指定していない codex セッションは `~/.codex/config.toml` の既定がそのまま効くので、
そちらを読んで出す。`/model` で変えたセッションはその値を出す。

一覧の列はモデル名が長いため、端末が 140 桁以上のときだけ出す。狭いときは
タイトルと作業ディレクトリを潰さないよう省き、詳細パネルのほうで確認する。

一覧の「タイトル」は Codex 自身が生成した会話タイトルを表示する。「作業ディレクトリ」は
実行状態にかかわらず、そのセッションが作業する場所を表示する。

## 会話を遡る

会話画面の `Ctrl+U` / `Ctrl+D` で 2 行ずつ。`Shift` を足すと 5 行ずつ。
マウスホイールでも同じだけ送れる（一覧では選択が動く）。

**通常の左ドラッグで文字を選び、マウスを離すとコピーする。F2は不要。**
一覧・詳細・会話・ログを含む全画面の、現在表示されている範囲が対象。
選択範囲を背景色で示し、選択中だけ画面更新を停止する（AIの処理は継続する）。
`Esc`は選択だけを解除し、文字入力・ホイール操作ならそのまま通常操作へ戻る。
選択中の`Ctrl+C`は再コピーとなり、タスク中断や編集中の入力消去はしない。
単なるクリックではコピーしない。画面外への自動スクロール選択は未対応で、リサイズ時は選択を解除する。

WSLでは`/mnt/c/Windows/System32/clip.exe`を非同期・3秒制限で使用する。
日本語はUTF-16LEで渡し、Windows TerminalのOSC52によるハングを避けるため、
この経路が失敗してもOSC52へ自動切替しない。Windows直接実行でも`clip.exe`を使う。
その他の環境はOSC52対応端末が必要（端末のクリップボード許可設定にも依存する）。
コピーを連打しても子プロセスは同時に1つだけ。完了前の再選択は、完了後に`Ctrl+C`で再試行する。

予備として`F2` / `Alt+C`の**端末標準コピー選択モード**も残している。
自動コピーが使えない場合は、`F2` → ドラッグ → `Ctrl+Shift+C`でコピーし、
`F2` / `Esc` / `Alt+C`で戻る。この予備モードではマウス報告・全描画・解除以外の入力を停止する。

会話画面の `↑` / `↓` は、複数行または折り返した入力の中ではカーソルを上下へ動かす。
先頭・末尾を越えたときだけ、自分が送信したプロンプト履歴へ移る。入力途中の文章は
一時的に退避され、履歴の末尾を越えて戻ると復元される。再起動前の送信履歴も対象になる。
長い入力は画面幅で折り返し、入力欄を最大10行まで広げる。それより長い場合は、
カーソルのある範囲へ自動的に表示が追従する。控えの編集画面も同じように追従する。

複数行の貼付けは、CR・CRLF・LFの改行を入力欄用のLFへ統一し、空行や字下げを保持する。
ブラケットペーストの受信中は、長文が分割されて届いても終端まで待ち、途中の改行で送信しない。
貼付け後にEnterを押すと送信する（送信時の先頭・末尾の空白除去は従来どおり）。

`Ctrl+Shift+U` は、端末が修飾を報告しない限り `Ctrl+U` と同じバイトで届く。
起動時に xterm の modifyOtherKeys（水準 1）を立てて報告させているが、
対応していない端末のために `Alt+u` / `Alt+d` も 5 行ずつにしてある。
前回までのやり取りも起動時に読み戻すので、落として立ち上げ直しても遡れる。
上下に続きがあるときは `↑ さらに N 行` と出る。

一覧の左端の印は、動いている間は回る印、止まっていて**まだ見ていない結果**が
あれば `✓`（成功）か `×`（失敗）。その会話を開くと消える。

## 次に送るプロンプト

Codexの実行中も、会話入力欄に追加の依頼や方向修正を書いて`Enter`で送れる。
同じ実行中ターンへ追加指示として渡し、受け付けられた文章を会話履歴に表示する。
現在のコマンド等の処理状況により、反映まで時間がかかる場合がある。

途中送信の受付を確認できない場合は、その文章を「控え」に保存して会話欄に理由を表示する。
通信が切れた場合は受付済みの可能性もあるため、再送前に会話履歴を確認する。
Claudeと更新前から実行中の`codex exec`は途中送信に未対応。更新後に開始するCodexターンから利用できる。

Codexの接続にはApp Serverの`turn/steer`を使う。workerとApp Serverは実行中だけ起動し、
完了時に終了する。ダッシュボードを閉じた場合も実行は続き、再起動後に出力の追跡と途中送信を再開できる。
接続は標準入出力と同じOSユーザーのみ接続できるUnixソケットを使い、TCPポートは開かない。
既存のCodex認証・設定を使い、追加のAPIキー設定は不要。
仕様: [Codex App Server](https://learn.chatgpt.com/docs/app-server)。

作業が終わったあとに送りたいことを、何件でも控えておける。順番は持たない。

| | |
|---|---|
| `e` | 控えを 1 件書き足す（会話中は `Alt+e`） |
| `p` | 控えの一覧を開く（会話中は `Alt+p`）。`↑↓` で選び `Enter` で送る |

**控えは自動では送られない。** 送るのは一覧で選んで `Enter` を押したときだけで、
作業が終わっても、`Enter` を押しても、勝手には出て行かない。
返答を見てから別のことを頼みたくなる場面のほうが多く、
一度送ってしまうと取り消せないため。

## スラッシュコマンド

会話で `/` を打つと候補が出ます。`Tab` か `↑↓` で選んで `Enter` で確定、
もう一度 `Enter` で送ります。

```
  /code-review                                        1/7
  /compact
  /config
  /context
┌────────────────────────────────────────────────────────┐
│ > /co▏                                                 │
└────────────────────────────────────────────────────────┘
 [Tab/↑↓]候補を選ぶ  [Enter]決定  [Esc]やめる
```

候補は**CLI が返した実際の一覧**です（起動時に使用量と一緒に取得しています。
モデル呼び出しは起きません）。存在しないコマンドは出ません。`/doctor` のように
端末でしか動かないものも除いてあります。

`/usage` `/context` `/compact` などは CLI 側で処理されるので、**トークンを
消費しません**。

**codex には出ません。** codex は `exec` モードでスラッシュコマンドを解釈せず、
ただのプロンプトとして送られてトークンを消費するためです。うっかり送ろうとすると
確認の表示が出ます。

### 承認

権限が足りずにツールが拒否されると、承認待ちになります。何をしようとしたかが
**差分まで見える**ので、`y` で許可するとその操作だけを通して再実行します。
`a` を押せば以後そのツールは常に許可します。

### 既存の会話を取り込む

端末で直接始めた会話も一覧に取り込めます。`n` →「追加方法」を
**既存の会話を取り込む** に切り替えると、保存されている会話が新しい順に並びます。
選ぶ前に中身が見え、取り込むと**これまでのやり取りがそのまま会話に入ります**。
Codex の一覧には Codex 自身が生成した会話題名を表示します。生成題名がない会話だけ、
最初の投稿を見出しとして表示します。
取り込んだ会話は、再起動後も CLI 側の元ログから過去のやり取りを読み戻します。
Codex の会話が resume によって複数の rollout に分かれていても、古い順に束ねて表示します。

### セッション開始からの集計とトークングラフ

CLI側の元ログが残っているセッションは、一覧・詳細・セッション履歴の
**コンテキスト、経過、実働、タスク、編集、実行、トークン**を、
ダッシュボードへ取り込んだ時点ではなくCLIセッションの開始時点から集計します。
元ログが古く値を持たない項目は、推測せずダッシュボードで確認できた値へ戻します。

`s`で統計を開くと、セッションごとに会話1回あたりの消費トークンを棒グラフで確認できます。
`←` / `→`（`h` / `l`）でセッションを切り替え、`↑` / `↓`やPage Up / Page Downで
全ターンをスクロールします。各ターンには入力、出力、キャッシュ入力、取得できる場合は
推論トークンと所要時間も表示します。終了前のターンは「進行中」として区別します。

月次集計だけは従来どおり、ダッシュボードで管理を始めた時点の基準との差分です。
既存会話の過去分が今月の実績へ混ざることはありません。ログは複製せずストリームで1件ずつ
解析するため、複数の大きなログを同時にメモリへ載せません。

### ネットワークが切り替わっても続きます

WiFi を切り替えると、実行中のセッションだけを止めて自動で復帰させます。
このとき**元のプロンプトは再送しません**。「未完了なら続きから」と状態確認を
挟むので、同じ編集が二重に入りません。

### サブエージェント

claude がサブエージェントを使うと、詳細に種別・使用ツール・消費トークン・
作業時間が出ます。

### 数字はすべて実測です

- **コンテキスト** — claude は正確値、codex は概算（`~` が付きます）
- **稼働率** — 実際に動いていた時間の割合
- **トークン** — 実際の消費量
- **使用量** — CLI が返す残量そのもの

全期間値とターン別グラフはCLIログから復元し、月次値とは別に保持します。

実行中タスクは、所要時間を取得できた完了ターンが3件以上ある場合だけ、詳細欄に
`目安 12:34頃`のような完了時刻を表示します。過去ターン所要時間の中央値による参考値で、
内容やツール待ちによって大きく変わります。中央値を過ぎた場合は「超過」と表示します。

### Codexのthread-store conflict

`thread-store conflict` / `already has an active writer`は、同じCodex会話を別の画面や
プロセスが書き込み用に開いている状態です。会話を壊さないためのCodex側の排他制御なので、
ロックファイルを手動削除しないでください。もう一方のCodex画面を終了してから再実行するか、
ダッシュボードの`N`で新しいセッションへ引き継ぎます。ダッシュボード側でも、このエラーは
原因と対処を日本語で表示します。

## スラッシュコマンド

claude は本体のコマンドをそのまま使える（候補も本体が返した一覧から出す）。

codex は非対話モード（`codex exec`）でスラッシュコマンドを解釈しないため、
よく使うぶんだけダッシュボード側で答える。CLI を呼ばないので実行の枠を使わない。

| | |
|---|---|
| `/status` | 状態・コンテキスト・使用量・作業場所 |
| `/model` | いまのモデルと選べる一覧。引数を付けると変更（次のターンから） |
| `/sandbox` | サンドボックスの設定を見る |
| `/compact` | コンテキストを圧縮する |
| `/help` | 使えるコマンド一覧 |

`/model` の一覧と既定値は codex 自身が置いているファイルから読む。推測はしない。

- `~/.codex/config.toml` — 既定のモデルと推論の深さ
- `~/.codex/models_cache.json` — codex が取得したモデル一覧（`visibility: list` のみ）

これ以外を codex に打った場合は送らずに知らせる。黙って送ると、ただの指示文として
モデルに渡ってしまうため（`docs/phase0/FINDINGS.md` §9）。

## ダッシュボードを閉じても作業は続く

同じ作業ディレクトリでも別セッションを並行実行する場合は、
`~/.agent-dashboard/config.json`の`workspace.serializeByCwd`を`false`にして再起動する。
既定値の`true`では、同じディレクトリは従来どおり順番待ちになる。
この設定は通常の実行、再起動後の実行追跡、ネットワーク復帰に適用する。
設定画面（`,`）でも「同じディレクトリの実行」を確認できる。

`workspace.autoWorktree`は新規作成時の作業場所の分離を指定する別設定。
並行実行を許可しても、既存の作業ディレクトリやworktreeを移動・削除することはない。
同じファイルを同時に編集すると競合するため、セッション間で担当ファイルを分けること。
同じ会話IDの二重実行は並行設定でも拒否する。

子プロセスは切り離して起動し、出力はファイルに書かせる。パイプで受けると、
ダッシュボードを閉じた瞬間に読み手が居なくなり、子は次に書いたところで死ぬ
（`docs/phase0/FINDINGS.md` §11）。

立ち上げ直すと、控えておいた PID が生きているセッションは「実行中」のまま戻り、
出力ファイルを読み直して続きから追いかける。指示を控えに戻して再送信させることはしない。
子が死んでいれば従来どおり中断扱いにして、指示を控えへ戻す。

## データの置き場所

```
~/.agent-dashboard/
  config.json            設定
  dashboard.json         画面の状態
  history.json           月次の集計
  sessions-meta/*.json   セッション（識別名・集計・下書き・CLI セッション ID）
  logs/<id>/
    raw.jsonl            CLI の生出力（無加工）
    tasks.jsonl          タスク履歴
    current.jsonl        実行中の子プロセスの出力（ターンごとに上書き）
  worktrees/<id>/        git worktree
  locks/                 実行ロック
```

置き場所は `AGENT_DASHBOARD_HOME` で変えられる（旧名の `VO_HOME` も受け付ける）。

かつては `~/.virtual-office` だった。旧名のディレクトリが残っていれば起動時に一度だけ
`~/.agent-dashboard` へ移す。ただし移すのは新しい方がまだ無いときだけで、両方あるときは
何もせず起動時に知らせる（旧版のダッシュボードが動いたまま終了して旧名へ書き戻した場合に、
新しい状態を古いもので潰さないため）。

```

同じディレクトリに 2 つ目を追加すると、git リポジトリなら自動で worktree を
切って隔離します。アーカイブ時、未コミットの変更があれば worktree は消しません。

設定は `config.json` を編集して再起動してください。現在の値は `,` で確認できます。

## 開発

```bash
npm test          # オフラインのテスト（速い）
npm run typecheck # 型チェック
npm run check     # 上の両方
npm run test:live # 実 CLI を叩くテスト（課金と時間がかかります）
npm run demo -- --plain   # 画面をテキストで確認
```

- 実行時の依存パッケージはありません
- テストは Node 内蔵のランナーを使います
- 画面のテストは色を落としたプレーンテキストで検証するので、レイアウト崩れが
  機械的に検出できます

- `docs/phase0/FINDINGS.md` — CLI の実挙動を採取した結果
- `docs/NETWORK-CHECK.md` — ネットワーク復帰の確認手順
